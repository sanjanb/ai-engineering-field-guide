**"Backend Tech Stack Burger"** specifically optimized for an **early-stage startup**, prioritizing maximum flexibility, low cost, and fast iteration speed while product-market fit (PMF) is still uncertain.

---

### The Backend Burger Stack (Layer by Layer)

| Stack Layer | Recommended Tech | Strategy & Rationale |
| --- | --- | --- |
| **Containerization** | None (Serverless) | Skip custom container orchestration to preserve speed and flexibility; serverless functions package as containers under the hood anyway. |
| **Architecture** | Serverless | Pay strictly for execution usage with no server provisioning or maintenance overhead. |
| **CI / CD** | GitHub Actions | Ready-to-use pipeline integration without hosting dedicated build servers. |
| **API Protocol** | REST | Standard, widely understood client-server interface. |
| **Version Control** | GitHub | Standard hosted VCS. |
| **Caching** | Browser Cache & CDN | Leverage edge caching (bundled free with hosts like Vercel/Netlify or via Cloudflare). |
| **Framework** | Next.js (on Vercel) | Unified stack running Express under the hood for backend routes. |
| **Testing** | Basic Unit Tests Only | Avoid heavy E2E test suites early on; defer full testing pipelines until after achieving PMF. |
| **Primary Laguage** | TypeScript | Shared language across front-end and back-end to reduce context switching. |
| **Database** | Firebase / Aurora Serverless | Use hosted document DBs (Firebase/Firestore) for simple schemas or Aurora Serverless for relational data models. |

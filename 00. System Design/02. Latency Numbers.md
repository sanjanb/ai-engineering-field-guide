This guide covers the core concepts from the ByteByteGo video **[Latency Numbers Programmer Should Know](https://www.youtube.com/watch?v=FqR5vESuKe0)**.

The primary goal in system design is not to memorize exact numbers, but to build an **intuitive sense of scale and relative orders of magnitude**. Physical limits (like the speed of light in fiber) keep cross-continent network latencies relatively fixed, whereas storage and memory hardware continue to evolve.

---

## 1. Time Units Refresher

Before looking at the hardware operations, keep the order of magnitude scale in mind:

* **1 Nanosecond (ns)** = $10^{-9}$ seconds (1 billionth of a second)
* **1 Microsecond ($\mu$s)** = $10^{-6}$ seconds (1 millionth of a second) $= 1,000\text{ ns}$
* **1 Millisecond (ms)** = $10^{-3}$ seconds (1 thousandth of a second) $= 1,000\ \mu\text{s} = 1,000,000\text{ ns}$

---

## 2. Latency Scale Breakdown

### Sub-Nanosecond ($< 1\text{ ns}$)

* **CPU Register Access & Clock Cycle:** Accessing CPU registers takes a fraction of a nanosecond. Registers are ultra-fast, but extremely limited in capacity.

### $1 - 10\text{ ns}$

* **L1 & L2 Cache Access:** Reading from L1 (~1–2 ns) or L2 (~3–5 ns) caches.
* **Branch Misprediction Penalty:** A branch mispredict forces the pipeline to flush and costs ~20 CPU clock cycles (~5–10 ns).

### $10 - 100\text{ ns}$

* **L3 Cache Access:** Taking tens of nanoseconds.
* **Main Memory (RAM) Reference:** Referencing RAM takes ~100 ns—roughly **100x to 200x slower** than accessing a CPU register.

### $100 - 1,000\text{ ns}$ ($0.1 - 1\ \mu\text{s}$)

* **MD5 Hashing:** Hashing a 64-bit number takes ~200 ns.
* **Linux System Call (Kernel Trap):** A minimal system call overhead takes ~700 ns (excluding the time required to execute the system function itself).

### $1 - 10\ \mu\text{s}$

* **Thread Context Switch:** Switching context between Linux threads takes a few microseconds under best-case conditions.
* **Memory Copy:** Copying 64 KB of data sequentially in RAM takes a few microseconds.

### $10 - 100\ \mu\text{s}$

* **NGINX Proxying:** Processing a simple HTTP request takes ~15 $\mu$s.
* **Sequential RAM Read (1 MB):** Reading 1 MB sequentially from main memory takes ~15 $\mu$s.
* **SSD Read (8 KB Page):** Reading an 8 KB page from a solid-state drive takes ~100 $\mu$s.

### $100 - 1,000\ \mu\text{s}$ ($0.1 - 1\text{ ms}$)

* **Same-Datacenter Network Round-Trip:** Round-trip time within a modern cloud availability zone takes ~100–500 $\mu$s.
* **SSD Write (8 KB Page):** SSD writes (~1 ms) are roughly **10x slower** than SSD reads.
* **Redis / Memcached Key Read:** A typical in-memory cache lookup over the local network takes ~1 ms client-side.

### $1 - 10\text{ ms}$

* **Inter-Zone Network Latency:** Round-trip communication across distinct availability zones in the same cloud region takes a few milliseconds.
* **Mechanical Hard Drive Seek Time:** Spinning disk (HDD) seek time takes ~5 ms due to mechanical arm movement.

### $10 - 100\text{ ms}$

* **Cross-Country Network Round-Trip:** Round-trip between US East Coast and West Coast (or US East Coast and Europe) takes ~30–100 ms.
* **Sequential RAM Read (1 GB):** Reading 1 GB sequentially from memory takes tens of milliseconds.

### $100 - 1,000\text{ ms}$ ($0.1 - 1\text{ s}$)

* **TLS Handshake:** Establishing an encrypted connection requires multiple network round-trips (~250–500 ms depending on distance).
* **Password Hashing (bcrypt):** Intentional security delay takes ~300 ms to make brute-force cracking computationally expensive.
* **Cross-Ocean Network Round-Trip:** US West Coast to Singapore round-trip takes hundreds of milliseconds.
* **Sequential SSD Read (1 GB):** Reading 1 GB sequentially from an SSD takes up to 1 second.

### $> 1\text{ Second}$

* **1 GB Regional Network Transfer:** Transferring a 1 GB payload over the network within the same cloud region takes ~10 seconds.

## 3. Practical System Design Rules of Thumb

| Operation Tier | Relative Speed | Core Engineering Insight |
| --- | --- | --- |
| **RAM vs. Disk** | RAM is ~1,000x faster than SSD | Keep hot data and indexes in memory whenever possible. |
| **SSD vs. HDD** | SSD is ~50x faster at random access | Avoid mechanical hard disks (HDDs) for random read/write workloads. |
| **Sequential vs. Random** | Sequential reads are up to 100x faster | Design data stores using append-only logs (e.g., LSM trees) to leverage sequential speed. |
| **Network vs. Memory** | Datacenter network is ~10,000x slower than RAM | Prefer batching requests over making multiple small RPC/network calls. |
| **Geography** | Light travels in fiber at ~200 km/ms | Global latency is bounded by physics; use CDNs and multi-region deployments to keep content near users. |

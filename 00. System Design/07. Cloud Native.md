## Cloud Computing vs. Cloud Native

* **Cloud Computing:** Running application workloads on infrastructure managed by cloud providers (e.g., AWS, GCP, Azure) rather than purchasing physical hardware. "Lifting and shifting" a traditional monolithic application to the cloud is cloud computing, but it is **not** cloud native.
* **Cloud Native:** A design architecture and blueprint specifically tailored to build web-scale, highly available, and resilient applications that can respond rapidly to changing demand without downtime.

## The 4 Pillars of Cloud Native

```text
                             Cloud Native Architecture
                                        │
     ┌───────────────────┬──────────────┴──────────────┬───────────────────┐
     │                   │                             │                   │
 Microservices      Containers &                 DevOps & CI/CD          Open Standards
 Architecture       Orchestration                                        & Ecosystem
```
### 1. Microservices Architecture

* Decomposes large monolithic binaries into small, single-purpose, loosely coupled services (e.g., separating an e-commerce platform into distinct *Cart*, *Payment*, and *Inventory* services).
* Allows separate engineering teams to take full ownership, deploying and scaling individual components independently.

### 2. Containers & Container Orchestration

* **Containers:** Package microservices with all code, dependencies, and configurations into lightweight runtime units.
* **Orchestration (Kubernetes):** Automatically manages container lifecycles across cluster nodes—monitoring health, balancing traffic loads, and auto-recovering failed pods.

### 3. DevOps & Automated CI/CD

* Emphasizes close alignment between development and operations teams.
* Uses **Continuous Integration (CI)** to continuously test and merge code into shared repositories.
* Uses **Continuous Delivery (CD)** to automate build deployment pipelines down to production environments without manual intervention.

### 4. Cloud Native Open Standards

Leverages open ecosystem standards to offload infrastructure concerns from application code:

* **Distributed Tracing:** Track multi-service request flows using tools like Jaeger, Zipkin, or OpenTelemetry.
* **Service Mesh:** Manage inter-service security, retries, and traffic routing via tools like Istio or Linkerd.

---

## When to Go Cloud Native

* **Simple / Small Applications:** Cloud native adds substantial operational complexity. A traditional monolithic or simple server architecture is often faster to ship and cheaper to maintain.
* **Large / Complex Applications:** Recommended when high availability, rapid release cycles, and independent scaling are critical business requirements.

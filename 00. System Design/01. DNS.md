### 1. Domain Name System (DNS) & Hierarchical Resolution

The Domain Name System acts as the internet's decentralized directory, mapping human-friendly hostnames (e.g., `google.com`) to machine-routable IP addresses.

#### The 4-Tier DNS Hierarchy

1. **DNS Recursive Resolver:** The initial contact point provided by ISPs or public providers like Cloudflare (`1.1.1.1`) or Google (`8.8.8.8`).
2. **Root Name Servers:** 13 logical root server IP addresses worldwide that maintain records for Top-Level Domain servers.
3. **Top-Level Domain (TLD) Name Servers:** Servers handling extension-specific domains like `.com`, `.org`, or country codes (`.uk`, `.de`).
4. **Authoritative Name Servers:** The definitive source of truth hosting actual resource records (A, AAAA, CNAME) for registered domains.

#### Recursive Resolution Walkthrough

```text
[Browser Cache] ──(Miss)──> [OS Cache] ──(Miss)──> [Recursive Resolver]
                                                            │
┌───────────────────────────────────────────────────────────┘
├─> 1. Query Root Server (. ) ───────────> Returns TLD Server IP (.com)
├─> 2. Query TLD Server (.com) ──────────> Returns Authoritative Server IP
└─> 3. Query Authoritative Server ───────> Returns IP Address (e.g., 142.250.190.46)
```

#### Zero-Downtime DNS Migration Gotchas

* **TTL Reduction:** Prior to updating records on a live system, lower the Time-To-Live (TTL) value (e.g., to 60 seconds) days in advance to purge long-cached records across intermediate resolvers.
* **Dual-Origin Operating:** Keep old origin servers active for a period following a DNS shift to handle traffic from legacy or non-compliant resolvers that ignore short TTLs.

### 2. Anycast Routing & Content Delivery Networks (CDNs)

To reduce physical latency for global user bases, modern edge networks leverage Anycast BGP routing alongside distributed Content Delivery Networks.

```text
                  ┌── Anycast IP (1.1.1.1) ──> [ Edge Node: Tokyo ]
[ Client Request ]──┼── Anycast IP (1.1.1.1) ──> [ Edge Node: London ]
                  └── Anycast IP (1.1.1.1) ──> [ Edge Node: New York ]
```

#### Unicast vs. Anycast

* **Unicast:** One-to-one mapping where a distinct IP address resolves to a single physical interface.
* **Anycast:** One-to-nearest mapping where multiple physical edge servers across different continents share the **exact same IP address**. Routers use Border Gateway Protocol (BGP) to route client requests to the network-topologically nearest node.

#### CDN Invalidation Strategies

* **Time-To-Live (TTL):** Standard HTTP `Cache-Control: max-age` directives determining cache freshness.
* **Active Cache Purging:** Origin servers trigger API-driven cache invalidations across edge Points of Presence (PoPs) upon data updates.
* **Cache-Busting / Content Hashing:** Injecting unique hashes into static asset paths (`bundle.a8f2c.js`) to enforce immutable long-term caching safely.

### 3. Load Balancing Algorithms & Reverse Proxies (L4 vs. L7)

Load balancers sit in front of application instances to distribute incoming request volume, prevent server saturation, and maintain high availability.

```text
 Client Traffic
       │
       ▼
[ Layer 4 Load Balancer ] (Transport level; TCP packet routing)
       │
       ▼
[ Layer 7 Load Balancer ] (Application level; HTTP inspection & TLS termination)
       │
  ┌────┴──────────────┐
  ▼                   ▼
[ Checkout Service ] [ User Profile Service ]
```

#### Layer 4 vs. Layer 7 Comparison

| Feature | Layer 4 (Transport Layer) | Layer 7 (Application Layer) |
| --- | --- | --- |
| **Inspection Scope** | IP addresses & TCP/UDP port headers | Full HTTP headers, cookies, URL paths, JSON payloads |
| **Processing Overhead** | Ultra-low latency; high packet throughput | Higher CPU overhead (requires TCP termination & SSL decryption) |
| **Capabilities** | Simple packet forwarding / NAT | Path routing (`/api/v1`), SSL termination, rate limiting, header manipulation |
| **Popular Tech** | AWS NLB, HAProxy (TCP mode), IPVS | NGINX, Envoy, AWS ALB, HAProxy (HTTP mode) |

#### Common Balancing Strategies

* **Round Robin / Weighted Round Robin:** Sequential distribution; effective for stateless nodes of uniform capacity.
* **Least Connections:** Directs traffic to instances processing the lowest active open sockets; ideal for long-lived TCP/WebSocket connections.
* **Consistent Hashing:** Maps requests to ring positions based on keys (such as `User_ID` or `Session_ID`), ensuring stable routing even when downstream server pools scale up or down.

## 1. Parametrized Recursion
In this approach, the function passes the result down through a parameter (like a running total). The function calculates the answer as it digs deeper into the calls and prints or uses the value at the very bottom (the base case). The functions themselves do not return values up the chain.
```python
def sum_parameterized(n, running_sum):
    # Base Case: When we've added all numbers down to 0
    if n == 0:
        print(f"Final Sum: {running_sum}")
        return
    
    # Pass the updated sum down to the next function call
    sum_parameterized(n - 1, running_sum + n)
# To find the sum of numbers up to 3 (3 + 2 + 1)
sum_parameterized(3, 0) 
```
## How the Data Flows (Going Down)
```text
sum_parameterized(3, 0)
    └── sum_parameterized(2, 0 + 3) -> sum_parameterized(2, 3)
            └── sum_parameterized(1, 3 + 2) -> sum_parameterized(1, 5)
                    └── sum_parameterized(0, 5 + 1) -> sum_parameterized(0, 6)
                            └── Base case hit! Prints 6 and returns nothing.

```
## 2. Functional Recursion
In this approach, the function returns the mathematical result back up to the previous caller. You break the problem down into a recursive formula. For the sum of $N$ numbers, the formula is:
$$\text{sum}(N) = N + \text{sum}(N - 1)$$ 
The function doesn't know the final answer until it hits the simplest known value (the base condition) and climbs back up the stack.
```python
def sum_functional(n):
    # Base Condition: The simplest version of the problem with a known value
    if n == 0:
        return 0
    
    # Recursive Step: Return the current number + the result of the remaining numbers
    return n + sum_functional(n - 1)

print(f"Final Sum: {sum_functional(3)}")
```
## How the Data Flows (Going Down & Coming Up)
Instead of carrying the answer with it, the function leaves a trail of unfinished additions on the call stack, then solves them in reverse:
```text
1. Going Down (Building the Stack):
sum_functional(3) -> waiting for 3 + sum_functional(2)
  sum_functional(2) -> waiting for 2 + sum_functional(1)
    sum_functional(1) -> waiting for 1 + sum_functional(0)
      sum_functional(0) -> Base Case hit! Returns 0.

2. Coming Up (Unwinding and Returning):
    sum_functional(1) resolves to: 1 + 0 = 1
  sum_functional(2) resolves to: 2 + 1 = 3
sum_functional(3) resolves to: 3 + 3 = 6

```
## 3. Complexity Analysis
For both methods calculating the sum of $N$ numbers, the complexities are identical:

* Time Complexity: $O(N)$
Because to calculate the sum of $N$, the function must execute exactly $N + 1$ times. The execution time grows linearly with the size of $N$.
* Space Complexity: $O(N)$
Because Python must keep all $N$ function calls alive simultaneously in the system's call stack memory until the base case is reached.

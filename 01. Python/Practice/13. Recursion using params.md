## 1. Printing a Number $N$ Times
To print a specific number (like 15) $N$ times, we use a counter parameter that decreases by 1 with each call. The base case triggers when that counter hits 0.
```python
def print_15_n_times(n):
    # Base Case: stop when count reaches 0
    if n == 0:
        return
    
    print(15)
    print_15_n_times(n - 1)  # Reduce count by 1

print_15_n_times(3)# Output:# 15# 15# 15

```
## 2. Printing 1 to $N$ (The Two Approaches)
The video covers two ways to print a sequence from $1$ up to $N$. Note that the instructor's terminology uses "Head" to mean processing on the way down, and "Tail/Backtracking" to mean processing on the way back up.
## Approach A: Head Recursion (Using a Tracking Variable i)
Here, we pass an extra tracking variable i that starts at 1 and grows until it hits $N$. We print before making the next recursive call.
```python
def print_1_to_n_head(i, n):
    # Base Case: stop when tracker passes n
    if i > n:
        return
    
    print(i)                  # 1. Action happens BEFORE the call
    print_1_to_n_head(i + 1, n) # 2. Recursive call

print_1_to_n_head(1, 4)# Output: 1, 2, 3, 4
```
## Approach B: Homework Challenge — Tail Recursion / Backtracking (No Tracking Variable)
The challenge asks you to print from $1$ to $N$, but you are not allowed to use an increasing tracking variable like i. Instead, you must pass $N$, call the function first, and let the printing happen as the stack unwinds.
```python
def homework_print_1_to_n(n):
    # Base Case
    if n == 0:
        return
    
    homework_print_1_to_n(n - 1)  # 1. Recursive call happens FIRST
    print(n)                       # 2. Action happens AFTER (on the way up)

homework_print_1_to_n(4)# Output: 1, 2, 3, 4

```
## 3. Dry Run & Recursion Tree (For the Homework Challenge)
To understand exactly why the homework code prints in ascending order (1, 2, 3, 4) even though $N$ starts at 4 and decreases, let's look at the recursion tree and stack behavior.
## The Recursion Tree (Going Down)
When you call homework_print_1_to_n(4), Python builds a stack of paused functions because the print(n) statement is forced to wait until the inner function call completely finishes.
```text
homework_print_1_to_n(4) 
   └── calls homework_print_1_to_n(3) [PAUSED: print(4) is waiting]
          └── calls homework_print_1_to_n(2) [PAUSED: print(3) is waiting]
                 └── calls homework_print_1_to_n(1) [PAUSED: print(2) is waiting]
                        └── calls homework_print_1_to_n(0) [PAUSED: print(1) is waiting]
                               └── Hits Base Case (n == 0) -> RETURNS!
```
## Unwinding the Stack (Backtracking Up)
Once n == 0 returns, the paused functions resume one by one from the last one added to the first one added (Last-In, First-Out):

   1. homework_print_1_to_n(1) resumes right after its recursive call line and executes print(1). Then it finishes.
   2. homework_print_1_to_n(2) resumes and executes print(2). Then it finishes.
   3. homework_print_1_to_n(3) resumes and executes print(3). Then it finishes.
   4. homework_print_1_to_n(4) resumes and executes print(4). The entire execution ends.

This stack delay flips the descending inputs (4, 3, 2, 1) into an ascending output (1, 2, 3, 4).

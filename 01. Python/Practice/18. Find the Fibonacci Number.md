## Method 1: Using Recursion
The recursive approach directly implements the mathematical formula: $\text{fib}(n) = \text{fib}(n-1) + \text{fib}(n-2)$.
```python
def fib_recursive(n):
    # Base Case: return 0 for n=0, and 1 for n=1
    if n == 0:
        return 0
    if n == 1:
        return 1
        
    # Recursive Case
    return fib_recursive(n - 1) + fib_recursive(n - 2)

print(fib_recursive(6))  # Output: 8
```
## Complexity Analysis:

* Time Complexity: $O(2^N)$ — Every function call splits into two more calls, generating a massive binary tree of calculations. For larger inputs (like $N=50$), this will freeze your computer because it recalculates the same values over and over.
* Space Complexity: $O(N)$ — The maximum depth of the call stack is proportional to $N$.

## ➡️ Method 2: Using a Loop (Iterative)
This approach uses a loop to build up to the $N$-th number from the bottom up, updating two variables as it steps forward.
```python
def fib_loop(n):
    if n == 0:
        return 0
        
    prev2 = 0  # Represents fib(i-2)
    prev1 = 1  # Represents fib(i-1)
    
    for _ in range(2, n + 1):
        current = prev1 + prev2
        prev2 = prev1   # Shift forward
        prev1 = current # Shift forward
        
    return prev1

print(fib_loop(6))  # Output: 8
```
## Complexity Analysis:

* Time Complexity: $O(N)$ — The loop runs exactly $N-1$ times, making it incredibly fast.
* Space Complexity: $O(1)$ — It only keeps track of a few tracking variables in memory, completely bypassing stack overflow risks.


## Fixing the Recursive Slowness: Memoization
If you want to keep the clean recursive structure but make it as fast as the loop, you can use Memoization (caching). By storing answers to subproblems in a dictionary, you eliminate redundant calculations:
```python
def fib_memo(n, memo={}):
    if n == 0: return 0
    if n == 1: return 1
    if n in memo: return memo[n]  # Return cached answer if it exists
    
    memo[n] = fib_memo(n - 1, memo) + fib_memo(n - 2, memo)
    return memo[n]

print(fib_memo(50))  # Output: 12586269025 (Runs instantly!)
```
(This brings the time complexity down from an unmanageable $O(2^N)$ to a lightning-fast $O(N)$).
